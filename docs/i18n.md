# i18n — code pages, non-Latin scripts, and RTL

## The one decision

For every string, chittie asks: **is it representable in the active code page?**
- **Yes** → printed as fast **code-page text** (the printer's built-in font).
- **No** → **rasterized** to an image via your injected `rasterizer` (the browser/OS shapes the
  glyphs, including ligatures and bidi). If no rasterizer is supplied, chittie **throws** rather
  than printing `?`.

You don't call this — `<Text>`/`<Row>` (and `smartText`) decide per string. You only (a) pick the
code page and (b) supply a rasterizer for scripts that need one.

## Picking a code page

Pass `codepage` to `render()` (default `cp437`, Latin):

| Script | Code page | Notes |
|---|---|---|
| Latin / Western | `cp437`, `cp858` (€) | default |
| Thai | `cp874` | encodable — prints as text |
| Japanese | `shiftjis` | encodable — prints as text |
| Arabic | `cp864` / `arabic` | *but see below — raster is usually better* |
| Sinhala / Tamil / Devanagari | — (none) | **must raster** |

```ts
render(<Receipt/>, { dotWidth: 384, codepage: 'cp874', rasterizer });
```

A code page is faster and sharper (native font), but only covers what the printer's ROM has.
Anything outside it — or any script with **complex shaping** — should raster.

## Non-Latin via the rasterizer

Sinhala, Tamil, Devanagari, and (recommended) **Arabic** have no reliable code page or need
shaping the printer can't do, so route them through the rasterizer — the canvas/Skia backend
shapes the glyphs correctly (joining forms, ligatures, **bidi**) and chittie prints the bitmap.
This is the chittie differentiator. See `examples/rasterizers`.

## Right-to-left (Arabic / Hebrew)

Two things matter for RTL:
1. **Shaping + bidi** — handled by the rasterizer (canvas does Arabic joining + bidi reorder when
   it draws the string), so raster your RTL text rather than using a code page.
2. **Layout** — a two-column `<Row>` reads the other way: the **label sits flush-right**, the
   **value flush-left**. Pass `rtl`:

```tsx
<Row rtl left="المجموع" right="Rs. 1,700" />   // label on the right, amount on the left
```

`rtl` mirrors both the raster path (`rasterizeRow`) and the code-page table path. It's per-row, so
mixed LTR/RTL receipts work.

## Summary

- Encodable → code page (set `codepage`); not encodable / complex → rasterizer (or it throws).
- Arabic/Hebrew: raster for correct shaping+bidi, and add `rtl` to any `<Row>`.
